# STM32F103C8T6 呼吸灯学习笔记

> 本文配合"呼吸灯"工程阅读（阻塞版 + 非阻塞版），用大白话讲清 GPIO、PWM、波形、阻塞/非阻塞这些概念。

## 一、功能需求

A0（PA0）上一颗共阳 LED 按一定频率呼吸（暗→亮→暗）；一个完整呼吸周期约 3.8s；PC13 心跳灯 500ms 翻转；分别用阻塞式和非阻塞式实现。

## 二、接线与极性

LED 长脚（正极）→ 面包板正极(3.3V)，短脚（负极）→ A0；

共阳接法，低电平点亮：点亮 = RESET，熄灭 = SET，所以亮度要反相（CCR = ARR - 亮度）。

## 三、GPIO：引脚到底是什么

- **GPIO = 通用输入输出**（General Purpose Input/Output），是单片机最基础的 I/O，就是学计算机时的"端口/寄存器"下放到引脚级。
- 一根引脚只会输出**高(3.3V)或低(0V)**，或者读取外界的高/低。
- 四种模式：
  - **输出**：自己出高低电平（流水灯点灯、PC13 心跳灯）
  - **输入**：读外部高低电平（按键、传感器）
  - **复用**：引脚交给内部外设管（呼吸灯把 PA0 交给 TIM2 输出 PWM，见 [breath.c](file:///e:/ek/呼吸灯/project/breath_103c/breath.c) 里的 `GPIO_MODE_AF_PP`）
  - **模拟**：接 ADC/DAC 的模拟电压
- 注意别和 **GPL**（开源软件许可证）混淆，不是一回事。

## 四、PWM：呼吸的底层原理

### 4.1 PWM 是什么

> **PWM = 用"快速开关"来假装"中间状态"。**

芯片只会输出 0V / 3.3V，没有中间电压。想让灯"半亮"？那就每秒开关很多次，让灯"亮的时间占 30%"——眼睛平均后看到的亮度就是 30%。

**PWM = 脉宽调制 = 调节"高电平脉冲的宽度"**。两个参数记住就行：

| 参数 | 作用 | 本工程 |
|---|---|---|
| 频率 | 一秒开关几次 → 决定"闪不闪" | 1kHz（每秒 1000 次） |
| 占空比 | 高电平占的比例 → 决定"亮度/功率" | 0%~100%，对应 CCR 0~999 |

### 4.2 计数器 + 比较器：硬件怎么实现

- 定时器里有个**计数器 CNT**，每 1ms 从 0 数到 999 再归零（一圈 1ms）。
- 你写的 **CCR 是一个关卡（阈值）**，比较器每时每刻比对：
  - `CNT < CCR` → 输出有效电平（灯亮）
  - `CNT ≥ CCR` → 输出无效电平（灯灭）
- 所以一个周期内**亮是一整段、灭是一整段**，不是均匀散布；"亮多长"完全由 CCR 一个数决定。
- 改亮度 = 挪关卡位置 = 改 CCR。硬件每微秒自动比对，软件每 30ms 挪一次就行。

### 4.3 两套速度：为什么"看不见开关，却看得见呼吸"

| 速度 | 干什么 | 眼睛 |
|---|---|---|
| 1ms 一圈（每秒开关 1000 次） | 制造"亮度等级" | 看不见，只看到平均亮度 |
| 30ms 一档、4s 一轮 | 制造"呼吸"动作 | 看得见 |

人眼"视觉暂留"约 50~60Hz，1kHz 比它快 20 倍，眼睛自动平均成稳定亮度。你看到的呼吸，是**慢的那条曲线**（4 秒里亮度从 0%→100%→0% 的轨迹），快的开关只是藏在底下的原材料。

## 五、亮度曲线：三角波 vs 余弦波

"波形"其实是**两种不同的东西**，别混：

- **引脚上的 PWM 方波**：物理信号，1kHz，硬件生成，是原材料；
- **亮度包络曲线**：软件节奏，是"亮度数字随时间变化的形状"，不是电信号。

包络曲线有两种常见选择：

| | 三角波（线性） | 余弦波（raised-cosine） |
|---|---|---|
| 形状 | 匀速增减，像锯齿 | 慢起→快→慢收，像钟形 |
| 代码 | 几行：`brightness += dir;` 到头掉头 | 查表 [breath.c](file:///e:/ek/呼吸灯/project/breath_103c/breath.c) `breath_lut[128]` |
| 手感 | 略"机械" | 更柔和，像真呼吸 |

**表不是手写的**：`breath_lut[k] = round((1 - cos(2πk/128)) / 2 × 999)`，一条公式算出 128 个数，k=0 最暗、k=64 最亮。想改曲线形状，改公式重新生成即可。

## 六、核心代码

呼吸由共享模块 [breath.c](file:///e:/ek/呼吸灯/project/breath_103c/breath.c) 提供：
`Breath_Init()` 初始化 TIM2 PWM，`Breath_SetBrightness(0, 亮度)` 设置 A0 亮度（内部写 `CCR = ARR - 亮度` 完成反相）。

阻塞版（[blocking_sync.c](file:///e:/ek/呼吸灯/project/breath_103c/blocking_sync.c)）：

```c
while (1) {
    Breath_SetBrightness(0, breath_lut[phase]);  // 更新 A0 亮度
    HAL_Delay(BREATH_STEP_MS);                   // 死等 30ms
    phase = (phase + 1) % SIN_N;                 // 推进一档
    if (HAL_GetTick() - last_heart >= 500)       // 每 500ms 心跳
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
}
```

非阻塞版（[nonblocking_sync.c](file:///e:/ek/呼吸灯/project/breath_103c/nonblocking_sync.c)）：

```c
while (1) {
    now = HAL_GetTick();
    if (now - last >= BREATH_STEP_MS) {          // 每 30ms
        last = now;
        Breath_SetBrightness(0, breath_lut[phase]);
        phase = (phase + 1) % SIN_N;
    }
    if (now - last_heart >= 500) {               // 每 500ms 心跳
        last_heart = now;
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
    }
}
```

## 七、阻塞 vs 非阻塞

**比喻**：阻塞 = 打电话等人，举着听筒干等，别的啥也干不了；非阻塞 = 发微信等人，该干嘛干嘛，时不时瞄一眼手机看回没回。

| | 阻塞版 | 非阻塞版 |
|---|---|---|
| 等 30ms 时 CPU 在干嘛 | 空转 | 还在跑循环，随时接新活 |
| 多件事同时做 | 难，只能排队 | 容易，每件事一个时间戳 |
| 代码 | 直观 | 略绕，多记几个时间戳 |
| 适用 | 简单顺序流程 | 多任务、实时性要求高 |

**流水灯工程是最好的对照**：阻塞版用一个 `tick` 计数推算所有时间（心跳 500ms = 5 个 100ms 节拍），想插一件 37ms 的事就得重排时间表；非阻塞版用三个时间戳（走灯/心跳/停顿）各算各的，互不干扰（参考 [e:\ek\流水灯\project\running_light_103c](file:///e:/ek/流水灯/project/running_light_103c)）。

## 八、小结

1. **PWM 从头到尾只有一件事：调"高电平的宽度"（占空比）**，用快速开关假装中间状态；
2. 硬件负责"每秒开关 1000 次"（计数器+比较器），软件只负责每 30ms 挪一次 CCR；
3. 呼吸曲线（三角/余弦）是"亮度数字随时间走的轨迹"，不是电信号；公式生成查表，不用手写；
4. 共阳低电平点亮，反相公式 CCR = ARR - 亮度 不能写反；
5. 阻塞式简单但占 CPU，非阻塞式用时间戳差值，易扩展到多路/多任务；
6. 流水灯用 GPIO 开关就够（不涉及亮度），呼吸灯才需要 PWM（要平滑变亮）。
